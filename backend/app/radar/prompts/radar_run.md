# Radar Run Request

Perform one complete Scientific Research Radar run using the configuration and prior-run context below. Execute all five stages internally and return the single structured response required by the API.

An empty history array means this is the first run. History is contextual memory generated by earlier runs: use it to avoid unnecessary repetition and identify supported changes, but verify all current claims from current sources.

## Configuration interpretation

- `topic` and `description` define the research question.
- `include_keywords` improve recall and relevance; they are not all mandatory matches.
- `exclude_keywords` are strong negative signals unless excluding a paper would remove clearly essential context.
- `target_audience` controls value judgments and briefing language.
- `reporting_from` and `reporting_to` define the primary publication or meaningful-update window.
- `maximum_papers` is the maximum number of papers returned and persisted, not a target that must be filled.
- `frequency` describes the intended cadence and should be reflected in the briefing metadata and framing.

No preferred-source list, seed papers, user feedback, custom value criteria, or custom digest goals are supplied in the current product version. Do not invent them; apply the system prompt's scholarly-source and audience rules.

## Compliance gate for this run

- Access sources only through the enabled tool and ordinary lawful public access. Do not bypass or work around any restriction.
- Do not treat a publicly reachable page, PDF, abstract, or user-provided item as proof of an open license or redistribution rights.
- Do not emit full text, copied abstracts, excerpts, figures, tables, or source-like reconstructions into any field. Only the structured response is stored.
- For every paper, provide a canonical link, access status, source basis, license when verified, and explicit warnings when rights or access are unknown or restrictive.
- When lawful use is ambiguous, keep only necessary bibliographic metadata and brief original analysis; never assert that an exception, commercial reuse, adaptation, redistribution, or text-and-data mining is permitted.
- Make the final transparency note clear that readers must verify original sources and applicable permissions before reuse or consequential reliance.

## Run requirements

1. Discover and deduplicate qualifying scientific or technical papers.
2. Assess every returned paper for relevance and audience value.
3. Produce one source-grounded summary per returned paper.
4. Analyze cross-paper signals and supported changes from prior runs.
5. Prepare the final structured briefing and concise Markdown rendering.

If no qualifying paper can be verified, return empty paper, relevance, and summary lists and clearly explain the search coverage and limitations. Do not fill gaps with unverified content.
